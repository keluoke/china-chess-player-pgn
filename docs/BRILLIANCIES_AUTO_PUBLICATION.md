# 实战妙手机器发布：待完成的生产契约

目标是把本机历史补扫和 GitHub 新增分析产生的候选，按**局面棋艺证据**自动分层、分批上线。棋手 FIDE ID、内部赛事 ID 和姓名只用于展示及可用链接，不决定质控资格。现有加密质控队列与只读汇总已实现；静态详情、棋谱分片和前台分页已支持扩容，精确机器发布事务及质量校准尚未完成，发布门禁保持关闭。

## 质控输入与分层

1. 只读取历史、新增各两分片的**当前版本**完整候选；历史基线必须无未完成棋局，两队列不能出现同一候选 ID。
2. 首轮 100 万、深度 500 万节点结果必须来自各自钉死的引擎/代码 profile，解密后逐条比对候选正文哈希。旧试验 profile 不获得发布权。
3. `brilliancy_publication_gate.py` 重放整局，验证指定着法、两引擎的独立搜索、合法 PV、节点与深度、接受/拒吃分支，以及从 PV 重新计算的材料变化。证据缺失保持 pending；冲突、搜索提前结束或非法证据隔离。试验 S/A 不能绕过此门禁。
4. 正式 S/A 阈值须在独立深度样本与对照局面校准，并版本化冻结。可先发布已完成且通过严格复核的高质量批次，后续继续复核剩余候选；不能以棋手身份、赛事 ID 或先验数量截断队列。

## 精确机器发布事务

- **收集**：只从认证后的加密 R2 检查点生成暂存包。包记录每个输入对象 key、ETag、密文 SHA-256/字节数、质控 profile、规则版本、候选 ID/正文哈希、通过/隔离计数；对外发布包只含公开字段和必要署名，不含私有路径、原始 HTML、密钥或完整引擎证据。发现输入 ETag 漂移即取消本批，重取新基线，禁止覆盖或重扫已完成局。
- **投递**：机器批准数据只写 `data/generated/brilliancies-approved/`；人工精选仍留在 `data/manual/brilliancies/`。复用现有精确 manifest、逐文件 SHA-256/baseSha256、不可变 main 基线和快进发布。投递失败只重试保存的 artifact，不回抓 PGN 或重跑引擎；main 有并发输入时重新从新基线组包，不能 rebase 派生快照。
- **派生与验证**：统一 `build_release_snapshot.py` 合并人工精选和机器批准层；原局哈希/指纹、合法走法、权限/署名、registry 权威、撤回状态和公共去来源化继续是硬门禁。每项有稳定 ID 和机器规则版本，可按 ID 精确撤回。重建、R2 回执、部署、普通线上 API/页面及 snapshot 正文一致才记为上线完成。
- **容量**：超过 255 条时改用 256 个两位 ID 前缀分片，PGN 与详情同分片，不生成逐条 PGN 文件；列表不含完整原局，页面每页最多 40 张卡片。分片各不得超过 2 MiB，部署继续遵守 19,000 文件、24 MiB 单文件的项目门禁。仍须用合成千条数据测文件数、体积、API 查询和浏览器交互，再打开机器发布开关。

## 验收与开放条件

先在暂存层做机器通过、非法证据、同 ID 冲突、撤回、FIDE ID 双缺失、赛事 ID 缺失、R2 ETag 冲突、main 并发输入和部署失败的演练。独立样本误判率及分层阈值验收通过后，才启用自动发布任务；首次 S 批次通过真实生产路径，再逐步开放 A 批次。任何未完成门禁只保留私有质控证据，不将候选冒充公开妙手。
