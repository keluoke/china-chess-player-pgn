# 赛事归一、分组呈现与查谱优先评估

评估日期：2026-09-15。依据已部署快照 `20260914T132352Z-73723fe6`，代码提交 `205699d6f0`。生产 `data/index/public-events.json` 与该提交正文一致。本文为方案与数据核验，不包含产品代码变更。

**建议采用同一个赛事身份层，同时解决名称、分组和棋谱关联；产品以能否查到棋谱为第一排序依据。优先利用已有广播原片，而非继续扩大重复抓取或逐条人工翻译。**

## 1. 名称待译的根因与处理方案

当前公共目录 2,281 条，其中 1,202 条标记名称待译（52.7%）：1,122 条来自 archive 类，80 条来自 other 类。这不是 1,202 个不同赛事系列；这些条目只有 1,015 个不同显示名称，同名记录还会因日期不同重复出现。

例如 `2026 Chinese Team Chess Championship | Men` 按 4 月 19、21、22、23、25、27 日成为六条目录记录。`10th Eastern Asia Youth Chess Championships 2026` 的不同组别/日期出现 36 条。后者不可仅因包含 Asian/Youth 就归入“亚洲青少年锦标赛”，东亚与亚洲必须区分。

现有中文映射表 205 行；公共目录仅 195 条带 canonicalEventID，归入 64 个父级 ID。`mapping_candidates()` 只挑 Chess-Results，最多 500 条，不覆盖待译最多的 Lichess 归档条目。非 TNR 赛事当前以 source + name + date 生成 ID，一项比赛跨日便可能被拆开。

建议：

1. 建立跨年份赛事系列词典：中文规范名、原文别名、旧译名、主办方/地区等消歧条件。年份、届次、站点、棋种、组别单独存储；新一届继承系列名，不重译整串标题。
2. 名称候选依次来自人工确认映射、同系列历史映射、广播已提供的中文 BroadcastName，再考虑新译名。原片中大量大师赛 BroadcastName 已是中文，不能只读英文 Event 标签。
3. 同届赛事关联使用系列、年份/届次、日期窗口、站点、棋种及组别；逐局关联再校验轮次、双方身份。模糊字符串只能产生候选，不能单独决定合并；East Asia/Asia、学校赛/世少赛、快棋/慢棋、男女组、不同站次必须有负例门禁。
4. 歧义队列以受影响棋谱数、重复片段数和核心赛事优先级排序。一次确认系列/别名服务以后所有年份；保留纠错和拆分记录。未确认的赛事继续显示原名，维护状态放后台，不给每条用户标题加“名称待译”。

复用 `Scripts/build_event_catalog.py` 和既有社区映射，不另建一套独立目录。现有 canonical 输出包含内部字段，不能直接整体接入公共前台；应输出遵守现有隐私与 Lichess 署名契约的公共父子投影。

## 2. 分组应该是赛事内部导航

当前 `public_catalog()` 按 TNR/单条 ID 合并，`docs/events.js` 逐条渲染；虽已有 `canonical_catalog()`，目录页没有消费父子结构。

建议结构：赛事系列 → 某年某届/某站 → 棋种与组别 → 轮次 → 对局。目录只列“某年某届/某站”，站次不同不能合在一个同年页面。组别用页内导航，少量用标签，多组用按年龄、性别、等级分组的选择器；棋种先切换，组别随后选择。

已有数据示例：2025 年上海青浦杯的 1227491、1227492、1227490、1227489、1227488 已共享父级 ID，却显示为五条独立记录。可呈现为：

```text
2025 全国国际象棋棋协大师赛 · 上海青浦杯
已收录 5 个组别                         [查看棋谱]

组别：棋协大师 / 男子候补大师 / 男子一级棋士 /
      女子候补大师 / 女子一级棋士

[棋谱]  [逐轮对阵]  [最终成绩]
```

“已收录 5 组”不意味着官方只设五组。父页可跨组查谱，但每局必须显示组别；排名与轮次对阵默认只显示所选组，不能汇总出一个跨组最终名次。旧 `?event=1227492` 地址继续定位男子候补大师组，返回棋手页时保留组别上下文。

## 3. 实际棋谱保有量及口径

当前去重棋局事实层有 76,519 条；80,208 是棋局与棋手的关联次数，不是独立棋局数。22,525 条事实尚未关联当前 registry 成员，不能因此从赛事查谱入口消失。已关联成员的独立棋局数为 53,994。

| 事实层保留的来源标签 | 去重事实数 | 占比 | 口径 |
| --- | ---: | ---: | --- |
| Chess-Results | 21,102 | 27.58% | 验证后的赛事 PGN 归档路径 |
| Lichess Broadcasts | 40,871 | 53.41% | 广播棋手投影及赛事交叉归档 |
| Static PGN | 14,546 | 19.01% | 历史静态 PGN，现均位于 chess-results 路径下 |

这不是各来源的独占贡献表，也不是“直接 HTTP 抓到棋谱”的比例。当前指纹去重遇到多源相同棋局，只保留优先来源标签，没有完整保留多源集合；导入、直接下载与旧静态归档也不能仅凭目录名区分。若按 CR 相关存储管线合看，是 35,648 条（46.59%），但不能把全部称为直接从 Chess-Results 下载。

需要给事实层保留多源 provenance 和采集方式，从而分别统计独有、重合、直接下载、离线导入。当前“有谱数量”还应增加非空着法、可解析、可播放的质量口径，不能仅用 Result 是否已结束判断棋谱是否有价值。

### 目录局数存在重复累计

`static_event_stats()` 从各棋手详情累加 gameCount，同一局两位棋手均入库时可能计两次。1227491 的目录 gameCount 为 178，赛事完整性报告 archivedGames/matchedPairings 均为 89。李杯 1356509 也出现目录 108、赛事档案 54 的差异。

必须从对局指纹集合计算组别与父级棋谱数，不能相加棋手包局数，也不能直接相加 CR 与广播两套统计。优先修正此处，再把“有谱 N 局”作为产品核心指标。

## 4. Lichess 是否覆盖大师赛与李杯

80 个月片（2020-01 至 2026-08）已逐片核对当前 manifest SHA-256，并完成离线解压扫描。78 片使用采集机现有文件，7、8 月使用生产 R2 已归档副本，没有重新访问赛事来源。manifest 总记录数 1,235,275；它是全球广播原片规模，不能作为本站可检索局数。

同时检查 Event 与 BroadcastName，得到以下明确命中的原始记录：

| 广播线索 | 原始记录数 | 限制 |
| --- | ---: | --- |
| 棋协大师赛相关广播 | 5,773 | 2025 年 4,620、2026 年 1,153；其中 2,182 条 Result 为 `*` |
| Chinese Youth Championships 2026 | 1,100 | 14 个组别；其中 3 条 Result 为 `*`，与 2026 李杯日期/组别存在明确关联线索 |
| Chinese Youth Championship 2024 | 264 | 8 个组别；仍需与对应年份赛事逐局核对 |

这些是元数据命中的原始 PGN 记录，尚未做本次审计范围内的跨来源指纹去重、着法完整性和全量对阵匹配，**不能宣称都是新增局，更不能宣称全台完整**。大师赛已命中盐城、盘锦、秦皇岛、北京、汕尾、重庆、安吉、合肥、齐齐哈尔，以及 2026 年珠海、青岛、深圳、安阳、嘉兴、绍兴、蚌埠、杭州、上海、聊城、儋州、呼和浩特等站。2025 盐城 BroadcastName 已细分六种组别，适合作为关联候选。

现行 `target_series_event()` 只接受慢棋亚少赛、世少赛，当前专项交叉归档是 75 个目标、70 个有广播、13,148 条广播归档记录；并未纳入李杯和大师赛。因此完整性报告中这两类的 lichessBroadcastGames 均为 0。与此同时，部分相关广播已经进入棋手通用查谱与 archive 目录，例如 `Chinese Youth Championships 2026` 有 35 条目录片段、706 条当前保留标签为 Lichess 的去重事实。**“未做专项关联”不等于“没有任何棋谱上线”。**

按当前分类标签（不是所有真实历史届次）统计，李杯 36 个目录组中有 3 组赛事档案含谱，共 164 局；大师赛 284 个目录组中有 24 组赛事档案含谱，共 2,960 局，283 组有完整性报告。名称/分类漏归仍存在：2024 B14 的 892907 留在 other，故不能把这两个数当作整个系列真实总库存或覆盖率。

建议首先离线重放已有原片，扩展到李杯与大师赛：先确认同届/站与组别，再按 round + 双方身份匹配，FIDE ID 优先，无 ID 走本场名单 playerNo 与规范化姓名，歧义隔离。保留未匹配残差、未结束记录和公开范围状态；已有有效棋谱可供查阅，完整性标签独立计算。没有来源公开证据的缺口不得安排无意义回抓。

Lichess 广播保留 CC BY-SA 4.0 署名，不能误用数据库其他部分的 CC0 声明。参考：[官方广播数据库](https://database.lichess.org/#broadcasts)。

## 5. 查谱优先的产品与实施顺序

现目录主标签是“完整赛果/元数据”，没有呈现 gameCount；结果是已有棋谱的广播条目仍被标成“元数据”，用户无法据此找到棋谱。

| 顺序 | 交付 | 验收 |
| --- | --- | --- |
| P0 | 同届/组别身份、唯一棋局计数、多源保留 | 上海示例按赛事档案为 89 而非 178；同局跨棋手/来源只计一次；不同组排名不串 |
| P0 | 李杯/大师赛既有广播离线关联 | 按届/站/组列出原始、已匹配、独有新增、重复、歧义与剩余记录；不能预先承诺把所有命中变成可用谱 |
| P1 | 历史系列词典与广播别名继承 | 已确认系列下一年无需重新翻译；东亚/亚洲、男女组、快慢棋、同年不同站不会误合并 |
| P1 | 父级赛事目录与组别页内导航 | 同届一张卡；旧链接仍定位原组；父页跨组局列表保留组别标签 |
| P1 | 查谱入口和有谱优先排序 | 默认显示有谱赛事，显式切换“全部赛事/仅赛果”；棋谱数量与可播放正文一致 |

主导航建议为“查棋谱、赛事、棋手”；查谱支持棋手/对手、赛事、年份、组别、轮次、执色、结果及已有开局字段。赛事页有 PGN 默认打开棋谱列表与棋盘，无 PGN 默认打开逐轮对阵，并明确“暂无可查看棋谱”。已有 PGN 无论赛果档案是否齐全都应能被发现；“公开范围已归档”和“全台完整”分别显示，不能共用一个“完整”标签。

不要把赛事 PGN 查询建立在“先找到已注册 FIDE 棋手包”上。无 FIDE ID 的棋手仍以本赛事名单身份查谱；跨赛事身份合并另行核验。目录卡片主信息为年份/站点、已收录组数、唯一可查看棋谱数、更新日期；“中国棋手数量”等易误导统计不应占主位置。

建议监控：有谱赛事可发现率、旧链接正确组别命中率、查谱零结果率、棋谱打开失败率、赛事归并误合并率、名称歧义待处理量。以用户实际打开一局棋谱为成功，而非目录行数或已抓赛事数。
