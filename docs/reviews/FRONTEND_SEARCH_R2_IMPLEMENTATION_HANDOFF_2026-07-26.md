# 搜索与排行榜第二轮修复交付（2026-07-26）

## 已修复

1. 静态站点中的 Markdown 改为默认不发布，仅
   `API.md`、`PUBLIC_METRICS.md` 进入公开白名单。`docs/reviews/`、采集手册和
   维护者运行文档继续保留在 Git 仓库，但不进入 Cloudflare 部署包。
2. `validate_public_privacy.py` 同时检查公开 JSON 和 Markdown；部署动作对最终
   组装目录再执行一次门禁，非白名单 Markdown 或内部信源/路径词命中即失败。
3. 排行榜先以 `no-store` 和一次性查询参数解析当前 `snapshotId`，随后用该 ID
   加载排行榜及展示姓名数据。页面只渲染数据声明的 controls/sexes，并要求
   schema v2 的每个 cohort/control/sex 维度完整；旧结构不再伪装成“0 人”。
4. 搜索构建对有汉字姓名但无拼音的记录生成 search-only 拼音别名，不写回
   registry/manual/community。保留默认读音，并补充单、曾、仇、解、查、覃、
   朴、区、乐九个常见多音姓氏读法；派生词进入前端索引、拼音分片和路由。
5. 搜索 Hero 只用于零查询态。有查询、棋手详情或赛事详情时收成 46px 工具条；
   棋手名/赛事名改为详情页 H1。

## 明确未采用

- 未上线“同拼音 FIDE ↔ 国内记录”文字桥。仅同拼音不足以构成成员级身份证据，
  即使标注“可能相关”也会放大同音重名误导。后续如做，应先提供可量化的歧义
  上限、候选回归集和独立的非身份关系 UI 契约。
- 未把派生拼音写回 registry，也未自动生成中文名；汉字到拼音只属于搜索层的
  可丢弃派生产物。
- 未用无约束的全多音字笛卡尔积。名字采用默认读音，仅姓氏使用小型显式特读表，
  避免索引膨胀和无关召回。

## 验收口径

- 组装部署包只能出现白名单中的两份 Markdown；历史内部 URL 返回站点 fallback，
  不得返回 Markdown 正文。
- 常规/冷缓存访问女子、快棋筛选均使用同一 snapshot 的 schema v2 数据。
- 国内记录的拼音可达率由原始字段约 53.8% 提升至约 98.6%；多音姓氏回归进入 CI。
- 桌面与移动端详情首屏以棋手名为视觉与语义主标题，搜索框保持可发现。
